It Will Not Swap Models Mid-SentenceIt Will Not Swap Models Mid-Sentence

A local gateway in front of many model providers. It retries a failing provider before the answer starts. If a stream breaks after that, it tells you, instead of quietly changing brains.

One Node process with no runtime npm dependencies, OpenAI- and Anthropic-compatible endpoints, an operations dashboard and Prometheus metrics. Fallback only happens before the first token commits.

  • TypeScript
  • Node.js 22+ (ESM)
  • OpenAI / Anthropic HTTP APIs
  • Circuit-breaker FSM
  • Prometheus metrics

There is a tempting trick in model routing. A provider dies halfway through a reply, so you hand the rest of the sentence to a different model and hope nobody notices the change in voice. Switching brains mid-sentence is easy, and RouteTok won’t do it. It will try another candidate before any text or tool output has committed. Once a stream has committed and then breaks, the proxy sends a truthful stream_interrupted frame and lets you decide what to do.

Behind that rule is a HealthRouter that ranks providers by success rate, consecutive failures, requests in flight and a running latency average, and a circuit breaker with three states. A failing route opens, sits out a cooldown, then lets exactly one probe through in the half-open state before it is trusted again.

All of it runs on Node’s built-ins. The only devDependencies are TypeScript, tsx and @types/node. The project publishes no latency benchmark, and the reading notes point out that it doesn’t, rather than letting a number appear from nowhere.

Under the hood

  • Hand-rolled Node `http` server (no framework) exposing OpenAI Chat Completions/Responses and Anthropic Messages on one `/v1` surface, with per-provider credentials and namespaced model IDs.
  • `HealthRouter` resolves explicit provider order, virtual routes (`auto`, `best`, `free`), custom cascades and a paid-OpenRouter fallback chain that runs ahead of AgentRouter last-resort routes.
  • Three-state circuit breaker (closed / open / half-open) opens on a consecutive-failure threshold or a failure-rate window, holds for `circuitOpenMs`, then admits one in-flight half-open probe.
  • Pre-output retry policy: fallback only before semantic or tool output begins; a committed stream reports `stream_interrupted` rather than splicing models.
  • Streaming proxy with SSE token/cost telemetry, Prometheus metrics, `x-router-*` attempt summaries and a browser-local Fieldbook (Compare, Room, Iteration Studio).

What it actually does

  • Zero runtime npm dependencies; devDependencies limited to TypeScript, tsx and @types/node
  • Health-aware pre-output failover across OpenAI- and Anthropic-compatible providers
  • Three-state circuit breaker with cooldown and a single in-flight half-open probe
  • Live SSE throughput metering, Prometheus metrics and cost accounting

What it doesn’t do (yet)

  • Fallback is pre-output only; a committed stream ends with `stream_interrupted`, never a splice.
  • Circuit opens on consecutive failures or a ≥50% failure window; half-open admits one in-flight probe.
  • Zero runtime npm dependencies; devDependencies are TypeScript, tsx and @types/node.
  • Legacy `agentrouter_router_*` Prometheus families are retained alongside planned `routetok_*` names.
