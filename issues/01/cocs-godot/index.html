    Same Fight, New BodySame Fight, New Body

    A native Godot 4.5 client for CoCS. Godot handles the hands, the eyes and the ears. The original Node.js server still decides what happened.

    CoCS-Godot · By SLOPTIMUS PRIME
    Open the repo ↗

    The short version

    Renderer
    Godot 4.5 · GL Compatibility
    Particle Lab
    8K–1M selectable (32K default)
    Authority
    Bundled Node.js server

    A playable prototype with separate labs for particles, shaders and materials. It targets Godot’s GL Compatibility renderer, and the four-chapter Quiet Relay campaign runs against a bundled local Node server.

    • Godot 4.5
    • GDScript
    • GDShader (.gdshader)
    • GL Compatibility renderer
    • Node.js authoritative server

    Porting a game usually means rewriting its rules and hoping they come out the same. CoCS-Godot skips the hoping. The authoritative match stays in the original Node.js simulation, and the Godot client speaks the same JSON WebSocket protocol as the browser build. The server cannot tell which front end just connected, which is the point.

    Everything you can feel is new. Recoil and sway come from a critically damped spring solved in closed form in motion_math.gd, so the weapon settles without the jitter of step-by-step integration. Custom shaders light the shields and weapon effects. A particle lab lets you choose anywhere from 8K to a million particles across GPU and analytic backends, and reports the frame cadence you actually got.

    It does not use Vulkan Forward+ or SDFGI. It uses GL Compatibility, and the repository is happy to tell you so.

    Under the hood

    • Native Godot 4.5 client connecting over WebSocketPeer to the original authoritative Node.js simulation, which retains ownership of movement, weapons, damage and objectives.
    • Presentation-only motion: motion_math.gd solves an exact critically damped spring in closed form (no Euler integration) for recoil recovery, sway and landing response.
    • Standalone particle lab with selectable 8K/32K/128K/512K/1M counts across GPU and analytic backends, reporting measured frame cadence.
    • GL Compatibility rendering with custom .gdshader material, shield and weapon-effect labs; the Quiet Relay campaign runs against a bundled local Node server.
    SOURCE EXCERPT // EXACT CRITICAL SPRINGgodot/source_operators/motion_math.gd: exact critical spring ↗
    static func spring(value: float, velocity: float, goal: float, rate: float, dt: float) -> Vector2:
	var offset := value - goal
	var j := velocity + rate * offset
	var decay := exp(-rate * dt)
	return Vector2(goal + (offset + j * dt) * decay, (velocity - rate * j * dt) * decay)
    07NO.105

    What it actually does

    • Native Godot 4.5 client wired to the original authoritative simulation
    • Speaks the same JSON WebSocket protocol as the canonical CoCS server
    • Exact closed-form spring motion for recoil, sway and landing
    • Particle, shader and material labs with selectable counts and measured cadence

    What it doesn’t do (yet)

    • Status: actively developed, playable prototype.
    • No Vulkan Forward+ or SDFGI; the project targets the GL Compatibility renderer.
    • The Node.js simulation stays authoritative; Godot is the client.

    If you open the repo, start here

    • Renderer: godot/project.godot sets rendering_method to gl_compatibility; no SDFGI or Forward+ references exist in the tree.
    • Protocol: godot/net/client.gd uses WebSocketPeer.send_text(JSON.stringify(frame)): the same JSON wire as CoCS.
    • Particle lab: godot/particle_lab/field.gd exposes counts [8192, 32768, 131072, 524288, 1048576] across GPU and analytic backends.
    • Campaign: port/campaign/PLAY.md launches The Quiet Relay against a bundled local Node.js server, not a self-contained offline engine.
