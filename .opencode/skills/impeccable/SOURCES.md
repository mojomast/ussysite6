## Text-only adaptation and parent attention

This is a **local reference edition**, not a functioning installation of the Impeccable engine. It contains only Markdown and license text. The implementation team chose a text-only import for this task; the user requested research and use of design skills, without specifying an installation method. Consequently:

1. **Do not run or install the launcher, `npx impeccable`, detectors, hooks, live servers, seed/catalog helpers, or generated-image tools from these documents.** Their command examples and `allowed-tools` frontmatter remain verbatim for provenance; they do not authorize execution under this request.
2. Upstream Setup explicitly supports a refused/unavailable launcher. When using that fallback, it asks for this separate message before the next tool call: **“Context loading did not run; I’ll read the existing project context directly.”** Read existing `PRODUCT.md`/`DESIGN.md` if present and the relevant local source/audit evidence. Do not invent missing context or claim the launcher ran.
3. `new-work.md` normally asks for discovery, a catalog roll, decision-page artifacts, surface contracts, finish review, and a documenter. For this reference-only workflow, use the team's **Darkroom Field Journal** direction and [research record](../../../docs/editorial-audit/design-research-2026.md), grounded in the user's established magazine identity and preservation constraints. Keep authored context and documentation within the active task's ownership.
4. Formal `critique` requires independent design/evidence assessments, delegation when available, and explicit degraded-report provenance otherwise. A single-context formal run calls for `⚠️ DEGRADED: single-context (<reason>)`. Its detector and persistence requirements cannot be fulfilled by this text-only bundle. Use its review criteria manually and clearly describe that limited method; do not report a full upstream command, deterministic scan, independent review, or computed health score that never happened. Any delegation must follow the parent task's permissions.
5. Formal `audit` is reporting-only. It measures accessibility, performance, theming, responsiveness, and implementation integrity; it does not silently apply fixes. Browser viewport evidence does not prove touch gestures or physical-device behavior.
6. `SKILL.md` calls for a batched desktop/mobile inspection, one fix batch, and at most one confirmation round in the build thread. Capture real content, check the actual user viewport, and report gaps rather than inventing passed checks.
7. Respect **brief wins** when generic rules conflict with this publication. `new-work.md` names several of the existing fonts as saturated defaults; `craft-floor.md` bans kickers/eyebrows; Anthropic favors very few families. The user explicitly retains six font roles and all factual copy/controls. Preserve those commitments, restrain each page, and remove empty decoration rather than useful section names or folios. These are deliberate project-specific adaptations, not a claim of literal conformity with every upstream rule.
8. Read `craft-floor.md` immediately before implementation, and use Read mode for articles. Smooth **Under the hood** expansion should explain state and preserve keyboard focus, disclosure semantics, reduced motion, and access to the complete source material.
